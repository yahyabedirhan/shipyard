# Changelog

What changed in each version of shipyard, newest first. 0.0.1 to 0.0.3 are GitHub releases with a download. 0.0.5 to 0.0.7 are plain tags on `main` that record the history between 0.0.3 and 0.1.0: no build was released for them, and the app and the `shipyard` command they build still report 0.0.3. There is no 0.0.4: its plan shipped in 0.0.5.

## Unreleased

- **A two-line lease banner.** The banner leads with why the agent took shipyard (or "Claude Code uses shipyard" when it gave no purpose), over a smaller line with what it's doing and how many wait; the logo names the agent. The time left ("4m 42s left") and Stop sit at the right edge, centred, and where the agent runs is the tooltip. A new step replaces the old one without the two drawing over each other, and the line cuts in the middle so "12s ago" stays whole. After Stop, the quiet line's button reads "Allow again" and sits where Stop did: [#216](https://github.com/yahyabedirhan/shipyard/issues/216) "Lease: Show the banner in two lines".
- **Open a project on GitHub from its header.** In the list layout, an open-in-browser icon shows beside a project's name on hover and opens its repository, as Return on the header does. Each pull request, issue and run count chip opens that kind's page (`/pulls`, `/issues`, `/actions`); in a project of several repositories it opens a menu of each repository's page with its count. The header's check, the new icon and a ping's ✕ share one smaller button size.
- **Agents can't fight you over the panel.** `shipyard screenshot` no longer opens a closed panel: it renders it off screen and says so on standard error. For 30 seconds after you close the panel, clicking elsewhere included, `shipyard panel open` is refused with the time it can open it again, so an agent can't reopen it in a loop.
- **See what an agent is doing in shipyard.** While an agent holds app control, the panel's banner shows what it's doing ("Taking a screenshot…", then "Took a screenshot · 12s ago"), so you can tell whether to leave the panel open. `shipyard control take --for "<purpose>"` adds why, in a few words, under the agent's name. `app status --json` reports both as the lease's `purpose` and `step`.

## 0.3.0 (2026-10-04)

Your own notes from Notion are listed under each project, with a new-note icon on its header, and agents post disposable status notices with `shipyard notify`: on the Mac, over your tailnet, or through the herdr-shipyard plugin, following your notification rules. It builds [#187](https://github.com/yahyabedirhan/shipyard/issues/187) "Spec: notes-and-notify, the user's notes in Notion and agents' notices", in [#206](https://github.com/yahyabedirhan/shipyard/pull/206).

- **`cli.toml`, the `shipyard` command's own settings.** Every machine's `shipyard` reads its own settings file, `cli.toml`: beside `config.toml` on the Mac, and `~/.config/shipyard/cli.toml` (honouring `XDG_CONFIG_HOME`) on a machine without the app. `config.toml` stays the app's, and no setting is in both. A missing file means the defaults; one that doesn't read, an unknown key included, stops the command that needs it with exit 1 and what's wrong. Its first table, `[notices]`, is for notices. ADR 0008 records the split, and the Linux `shipyard` now links TOMLDecoder to read it: [#189](https://github.com/yahyabedirhan/shipyard/issues/189) "cli.toml: the CLI's own settings file".
- **Notes in the menu.** Your own notes, kept in Notion with one database per project under a "Shipyard Notes" page (the skill's notes reference says how agents write them; ADR 0009), are listed under each project in a Notes group, newest first: the prefixed number, the title (or an untitled note's first line) and the labels. Archived notes stay out, notes never count toward attention, and clicking one opens it in Notion. Connect Notion… in the gear menu takes the token of a Notion internal connection, checks it and keeps it in the Keychain. Notes refresh every minute and when the menu opens; a failed query or a rejected token shows on the project, never as an empty list. `[defaults.notes] show` and a project's `notes = { show }` turn them off: [#192](https://github.com/yahyabedirhan/shipyard/issues/192) "Notes in the menu".
- **Notices on the Mac.** `shipyard notify "<title>" [--body <text>] [--from <label>] [--repo <owner/name> | --project <name>]` posts a status notice through the running app: a notification titled with the project and the title, never listed, counted or kept. It's filed as a ping is and shown when the project's rules select the new event `agent.notice`, which is in the default rules. It prints `shown` and exits 0 once shown; it exits 1 with why when notices are off for the project, no project takes it, shipyard's notifications are off in System Settings, or shipyard isn't running (it never starts the app); and 2 for arguments that don't read. A file that lists its own notification rules needs `agent.notice` added to see notices. The skill says when to ping and when to notify: [#190](https://github.com/yahyabedirhan/shipyard/issues/190) "Notices on the Mac: shipyard notify with a title and body".
- **The new-note icon.** Once Notion is connected, each project that shows notes has a pencil on its header (on its tab's summary line in the tabs layout). A click creates an empty note in the project's database and opens it in Notion, ready to type or dictate, and the menu lists it. The first time, it creates the database too, with the skill's fixed properties and a prefix from the project's name that no other database uses. While it works the icon spins; a failure (no token, no Shipyard Notes page shared, a rejected token, Notion out of reach) opens nothing and shows on the project until the menu opens again: [#196](https://github.com/yahyabedirhan/shipyard/issues/196) "The new-note icon on a project's header".
- **Notices on the poll route.** On another machine with no faster route to the Mac, `shipyard notify` leaves the notice with the herdr-shipyard plugin and prints `queued; shown within about 30 seconds if the Mac is awake`, exit 0; the plugin missing, too old to hold notices or refusing the notice exits 1 with why. The Mac's remote-ping poll collects each machine's notices once its pings are in, removes them there once read, and shows them by the same rules as any notice, dropping one more than ten minutes old when it arrives. Images aren't carried this way, and remote pings work as before, a plugin from before notices included. The skill's notices reference explains the routes and how to tell which one a machine uses: [#195](https://github.com/yahyabedirhan/shipyard/issues/195) "Notices on the poll route".
- **The rest of a notice's options.** `shipyard notify` takes every option a macOS notification offers: `--subtitle`, `--image <path>` (a PNG, JPEG or GIF of 5 MB at most, which the command reads and sends with the notice), `--sound default|none|<name>`, `--thread <key>` to stack related notices, `--level passive|active`, and `--id <id>`, which replaces the notice shown under that id in place; `shipyard notify withdraw <id>` takes it away and prints `withdrawn`. One click action, `--open <url>`, `--app <bundle id or name>` or `--herdr [<id>]`, runs as a ping's does, and up to three `--button "<label>=<action>"` each run their own (`open:<url>`, `app:<name>`, `herdr[:<id>]`). Two click actions, a fourth button, an unknown level or an image that can't be shown exit 2 with what was wrong. On the poll route the image is left out, an id replaces the notice still waiting, and `withdraw` reaches only a waiting one. Critical and time-sensitive levels, text replies and scheduled delivery aren't offered: [#193](https://github.com/yahyabedirhan/shipyard/issues/193) "The rest of a notice's options".
- **Notices over the tailnet.** A notice from another machine can reach the Mac within about a second, over your tailnet. On the Mac, `[notices] listen = true` in `config.toml` (off by default) has the app listen on 127.0.0.1 only, at `[notices] port` (47420 by default), which you expose with `tailscale serve --bg --http=47420 http://127.0.0.1:47420`; the app takes a notice only when Tailscale's `Tailscale-User-Login` is the Mac's own login (from `tailscale status`), and refuses requests from a browser. On the other machine, `[notices] app-machine = "<MagicDNS name>"` in its `cli.toml` (with `app-scheme` and `app-port` when `serve` needs others) sends `shipyard notify` and `shipyard notify withdraw` there: it waits up to 3 seconds (a second more per megabyte for an image) and prints `shown` or `withdrawn`, or exits 1 with why (refused, unreachable, no answer). A notice with a `--herdr` click or a `herdr` button can't go this way, since the Mac would focus its own Herdr: it exits 2, and the Mac refuses one that arrives anyway; leave `app-machine` out to send it through the poll route. Without `app-machine` the notice takes the poll route. The Linux `shipyard` now links the notices module, so `notify` works there. ADR 0010 records the exception to "a machine never reaches in": [#194](https://github.com/yahyabedirhan/shipyard/issues/194) "Notices over the tailnet".

## 0.2.0 (2026-10-03)

One agent at a time holds app control, and you see which: a lease the app enforces, a dot and a banner while an agent holds it, turns agents take on purpose, Stop to take shipyard back, and a notification when an agent starts and stops. It builds [#176](https://github.com/yahyabedirhan/shipyard/issues/176) "The agent lease: one agent at a time holds app control, and the maintainer sees it", in the agent-lease pull request; ADR 0007 records the design. [Release](https://github.com/yahyabedirhan/shipyard/releases/tag/v0.2.0).

- **The agent lease.** App control is leased to one agent at a time. An agent's first `shipyard app`, `panel` or `screenshot` command takes the lease and each later one renews it, until a minute after its last command and five minutes after it was taken at most. The app refuses another agent's command with exit 1, naming who holds shipyard, where, and when the lease ends. The `shipyard` command works out who the agent is on every call (its Claude Code session, else its own process), so agents pass nothing. `shipyard app status` needs no lease and reports it, as a `lease:` line and a `lease` object in `--json` (`null` when free). The control protocol is at version 2, so a `shipyard` and an app from different builds are told to reinstall: [#177](https://github.com/yahyabedirhan/shipyard/issues/177) "The lease refuses a second agent".
- **A relaunch keeps the lease.** `shipyard app open`, `app open --demo` and `app quit` need the lease, and `app open` against the running app renews it. When `app open` quits an app to launch another (a demo, or yours back), the launched app starts with the agent's lease, until the same end, so no other agent takes shipyard in the gap: [#179](https://github.com/yahyabedirhan/shipyard/issues/179) "A relaunch keeps the holder's lease".
- **Seeing who holds shipyard.** While an agent holds the lease, the menu bar icon carries a yellow dot and a banner tops the panel, in both layouts: the agent's logo and "Claude Code uses shipyard", over a smaller line with where it runs (its folder, or the whole Herdr pane id), the time left counting down each second, and how many wait. Both go when the lease ends, even with no command. `shipyard screenshot` leaves the dot and the banner out, the menu bar icon's included, unless `--with-indicator` keeps them: [#180](https://github.com/yahyabedirhan/shipyard/issues/180) "The maintainer sees who holds shipyard".
- **Taking turns.** `shipyard control take` holds shipyard on purpose for a longer run, until five minutes after it was taken, and `shipyard control release` gives it up for the next agent. With `--wait <seconds>` (an hour at most), a `take` from another agent waits in line, first come, first served, until it gets shipyard or its wait runs out, and `shipyard app status` counts the agents waiting; a waiting agent that has gone by the time shipyard is free gives it straight to the next. When the automatic holder doesn't fit, `SHIPYARD_CONTROL_KEY=<k>` in the environment names it for every `app`, `panel`, `screenshot` and `control` command, and `--key <k>` for one `take` or `release`. `control` runs on the Mac only, like `app`: [#178](https://github.com/yahyabedirhan/shipyard/issues/178) "Take, release and wait in line".
- **Stop takes shipyard back.** Stop in the lease's banner ends the agent's lease and keeps it out for five minutes: its next command, `control take` included, is refused with "the user took shipyard back; ask them before using it again". For those five minutes the panel shows "You took shipyard back from <Agent>" with Allow, which lets it back at once. An agent waiting in line gets shipyard as usual, and its banner shows above that line: [#181](https://github.com/yahyabedirhan/shipyard/issues/181) "Stop takes shipyard back".
- **Notifications when an agent starts and stops using shipyard.** The new events `control.started` ("Claude Code is using shipyard", over where it runs) and `control.ended` ("Claude Code is done with shipyard", over why: released, its lease ran out, or you stopped it) are in the default rules, and clicking either opens the panel. Only `[[defaults.notifications]]` decides them: a project's own list and a rule's `authors` don't apply, and the app warns about either. A file that lists its own `[[defaults.notifications]]` needs both added to hear of them. Renewals and relaunches post nothing, so one lease makes one pair: [#182](https://github.com/yahyabedirhan/shipyard/issues/182) "Notifications when a lease starts and ends".
- The shipyard skill teaches agents to take turns: [#183](https://github.com/yahyabedirhan/shipyard/issues/183) "Teach agents to take turns".
- The version bump, in the agent-lease pull request: [#184](https://github.com/yahyabedirhan/shipyard/issues/184) "Bump the version to 0.2.0".

## 0.1.0 (2026-10-03)

Agents steer and capture the app, each build carries only the modules it uses, the rough edges pings left are fixed, and releasing is written down for agents. It finishes every issue open on 2026-10-03, as [#160](https://github.com/yahyabedirhan/shipyard/issues/160) "Spec: clean-slate, every open issue finished, app control, modules by concern and the 0.1.0 release" planned, in the clean-slate pull request. [Release](https://github.com/yahyabedirhan/shipyard/releases/tag/v0.1.0).

- **App control.** On the Mac, `shipyard app open`, `quit` and `status` open, quit and ask the app; `shipyard panel open`, `close`, `fold`, `unfold`, `show-more` and `tab` steer its panel; `shipyard screenshot <file.png> [--appearance light|dark]` saves the open panel, and falls back to the app's own rendering, saying so, when the screen can't be captured; and `shipyard app open --demo <folder>` runs the app on that folder's configuration and state without touching yours. The requests go over a socket only your user can reach, and the shipyard skill and `AGENTS.md` teach agents the commands: [#166](https://github.com/yahyabedirhan/shipyard/issues/166) "Open, quit and ask the app from the shipyard command", [#167](https://github.com/yahyabedirhan/shipyard/issues/167) "Steer the panel from the shipyard command", [#168](https://github.com/yahyabedirhan/shipyard/issues/168) "Launch shipyard on demo data", [#169](https://github.com/yahyabedirhan/shipyard/issues/169) "Capture the panel from the shipyard command" and [#170](https://github.com/yahyabedirhan/shipyard/issues/170) "Teach agents app control, in the skill and AGENTS.md".
- **Modules by concern.** The Linux `shipyard` is built from the command and pings modules only, and the Mac's `shipyard` links reading `config.toml` and the control client but never the app's rules. Where a ping is filed is one interface with a Linux and a Mac implementation, not a platform check. ADR 0006 and the low-level design record the split. 0.1.0 is the first release with the Linux `shipyard` files and their `.sha256` files attached: [#164](https://github.com/yahyabedirhan/shipyard/issues/164) "Ship a Linux shipyard built from pings code only", [#165](https://github.com/yahyabedirhan/shipyard/issues/165) "The Mac shipyard links Config, never the app's rules" and [#161](https://github.com/yahyabedirhan/shipyard/issues/161) "Write the module design and ADR 0006 into the docs".
- **Ping fixes.** `shipyard ping` files against the `config.toml` the app reads, and is refused when every project it goes under hides pings. The app re-reads pings only when a ping changes, a `--herdr` ping focuses its pane in the named Herdr session it came from, a remote ping filed only after its selectors resolve notifies once, and a replaced ping's age starts again: [#126](https://github.com/yahyabedirhan/shipyard/issues/126) "The shipyard command reads the same config.toml as the app", [#127](https://github.com/yahyabedirhan/shipyard/issues/127) "Tell the agent when its ping shows nowhere", [#128](https://github.com/yahyabedirhan/shipyard/issues/128) "Re-read pings only when a ping changes", [#129](https://github.com/yahyabedirhan/shipyard/issues/129) "Focus --herdr pings from a named Herdr session", [#146](https://github.com/yahyabedirhan/shipyard/issues/146) "A remote ping filed under a project only after its selectors resolve still notifies" and [#150](https://github.com/yahyabedirhan/shipyard/issues/150) "Decide whether a replaced ping's age starts again".
- **Releases.** `AGENTS.md` gains a Releases section: an agent cuts a release end to end, then carries it, and any skill change, to the Mac and the remote machines. This changelog records 0.0.5 to 0.0.7, each tagged at the commit it ended on: [#162](https://github.com/yahyabedirhan/shipyard/issues/162) "Write how agents release and carry changes to the machines" and [#163](https://github.com/yahyabedirhan/shipyard/issues/163) "Record 0.0.5 to 0.0.7 in a changelog, with tags".
- **Docs and screenshots.** The README's three example screenshots are retaken with the current build, and the skill and the README name the limit that a remote ping's click can't switch the Mac's Herdr window to its machine: [#83](https://github.com/yahyabedirhan/shipyard/issues/83) "Retake the README's three example screenshots with the current build" and [#152](https://github.com/yahyabedirhan/shipyard/issues/152) "A remote ping's click can't switch the Mac's Herdr window to its machine".
- **A test audit** left one owner test per contract across the ping, CLI and Herdr tests: [#130](https://github.com/yahyabedirhan/shipyard/issues/130) "Audit the ping, cli and herdr tests after 0.0.6".
- Small leftovers from 0.0.2's final review are tidied: [#84](https://github.com/yahyabedirhan/shipyard/issues/84) "Tidy up small leftovers from 0.0.2's final review".
- **Faster CI.** CI runs once per pull request push and shares the SDK module cache: [#157](https://github.com/yahyabedirhan/shipyard/pull/157) "build: run ci once per pull request push and share the sdk module cache".
- The shipyard skill compares pinging from the Mac with pinging from another machine: [#158](https://github.com/yahyabedirhan/shipyard/pull/158) "docs(skill): compare pinging from the mac and from another machine, and start --from with the agent's name".
- Shipyard is licensed under MIT, and the bundled agent logos' notices are in `THIRD-PARTY-NOTICES.md`: [#159](https://github.com/yahyabedirhan/shipyard/pull/159) "docs: license shipyard under mit and give the bundled logos' notices a home".
- The version bump, in the clean-slate pull request.

## 0.0.6 (2026-10-02, tag only)

Pings from agents on your other machines, through Herdr, and faster builds.

- **Remote pings.** Agents on other machines send `shipyard ping` as on the Mac, and a blocked agent pings by itself through the herdr-shipyard plugin. The Mac reads each machine listed under `[remote] machines` through Herdr's own connection (never SSH), files, notifies and lists its pings, shows a quiet line for a machine it can't reach, and focuses the agent's pane on that machine when you click. The `linux cli` workflow builds static Linux `shipyard` files for each release: [#143](https://github.com/yahyabedirhan/shipyard/pull/143) "feat: remote pings, from agents on my other machines through herdr (0.0.6)".
- **Faster builds.** CI builds once, caches `.build` between runs, and bundles the app only on `main` and tags: [#142](https://github.com/yahyabedirhan/shipyard/pull/142) "ci: build once, cache .build and bundle only on main and tags".

Pings from agents through the `shipyard` command, plus what 0.0.4 planned: the project setup and the menu freeze fix.

New settings: `[defaults.pings]` `show` and `seen-window`, and `[herdr] terminal`: [#106](https://github.com/yahyabedirhan/shipyard/pull/106) "feat: pings, sent by agents through the shipyard cli (0.0.5)".

- **The project setup for agents**: [#90](https://github.com/yahyabedirhan/shipyard/pull/90) "chore: audit the repo with set-up-project and keep two memory notes", [#91](https://github.com/yahyabedirhan/shipyard/pull/91) "chore: adopt the skills repo's folder standard for agent records", [#92](https://github.com/yahyabedirhan/shipyard/pull/92) "refactor: rename context.md to glossary.md and update issue-tracker.md" and [#93](https://github.com/yahyabedirhan/shipyard/pull/93) "docs(agents): create an effort label only when it's missing".

## 0.0.1 (2026-09-26)

Shipyard's first release. [Release](https://github.com/yahyabedirhan/shipyard/releases/tag/v0.0.1).

- Every open pull request on the projects you pick, with issues and workflow runs if you turn them on; an attention count with seen marks; notifications for the events you choose; a list or tabs layout; keyboard navigation; at most 10% of your GitHub rate limit; one commented `config.toml` your agents can edit, with a JSON Schema; a guided first launch; and launch at login: [#21](https://github.com/yahyabedirhan/shipyard/pull/21) "feat: build shipyard 0.0.1, the core and the macos app".
