# Changelog

What changed in each version of shipyard, newest first. 0.0.1 to 0.0.3 are GitHub releases with a download. 0.0.5 to 0.0.7 are plain tags on `main` that record the history between 0.0.3 and 0.1.0: no build was released for them, and the app and the `shipyard` command they build still report 0.0.3. There is no 0.0.4: its plan shipped in 0.0.5.

## Unreleased

- **The agent lease.** App control is leased to one agent at a time. An agent's first `shipyard app`, `panel` or `screenshot` command takes the lease and each later one renews it, until a minute after its last command and five minutes after it was taken at most. The app refuses another agent's command with exit 1, naming who holds shipyard, where, and when the lease ends. The `shipyard` command works out who the agent is on every call (its Claude Code session, else its own process), so agents pass nothing. `shipyard app status` needs no lease and reports it, as a `lease:` line and a `lease` object in `--json` (`null` when free). The control protocol is at version 2, so a `shipyard` and an app from different builds are told to reinstall: [#177](https://github.com/yahyabedirhan/shipyard/issues/177) "The lease refuses a second agent".
- **A relaunch keeps the lease.** `shipyard app open`, `app open --demo` and `app quit` need the lease, and `app open` against the running app renews it. When `app open` quits an app to launch another (a demo, or yours back), the launched app starts with the agent's lease, until the same end, so no other agent takes shipyard in the gap: [#179](https://github.com/yahyabedirhan/shipyard/issues/179) "A relaunch keeps the holder's lease".
- **Seeing who holds shipyard.** While an agent holds the lease, the menu bar icon carries a yellow dot and a banner tops the panel, in both layouts: the agent's logo, "Claude Code in shop is using shipyard", the time left counting down each second, and how many wait. Both go when the lease ends, even with no command. `shipyard screenshot` leaves the dot and the banner out, the menu bar icon's included, unless `--with-indicator` keeps them: [#180](https://github.com/yahyabedirhan/shipyard/issues/180) "The maintainer sees who holds shipyard".
- **Taking turns.** `shipyard control take` holds shipyard on purpose for a longer run, until five minutes after it was taken, and `shipyard control release` gives it up for the next agent. With `--wait <seconds>`, a `take` from another agent waits in line, first come, first served, until it gets shipyard or its wait runs out, and `shipyard app status` counts the agents waiting. When the automatic holder doesn't fit, `SHIPYARD_CONTROL_KEY=<k>` in the environment names it for every `app`, `panel`, `screenshot` and `control` command, and `--key <k>` for one `take` or `release`. `control` runs on the Mac only, like `app`: [#178](https://github.com/yahyabedirhan/shipyard/issues/178) "Take, release and wait in line".
- **Stop takes shipyard back.** Stop in the lease's banner ends the agent's lease and keeps it out for five minutes: its next command, `control take` included, is refused with "the user took shipyard back; ask them before using it again". For those five minutes the panel shows "You took shipyard back from <Agent>" with Allow, which lets it back at once. An agent waiting in line gets shipyard as usual, and its banner shows above that line: [#181](https://github.com/yahyabedirhan/shipyard/issues/181) "Stop takes shipyard back".
- **Notifications when an agent starts and stops using shipyard.** The new events `control.started` ("Claude Code is using shipyard", over where it runs) and `control.ended` ("Claude Code is done with shipyard", over why: released, its lease ran out, or you stopped it) are in the default rules, and clicking either opens the panel. Only `[[defaults.notifications]]` decides them: a project's own list and a rule's `authors` don't apply, and the app warns about either. A file that lists its own `[[defaults.notifications]]` needs both added to hear of them. Renewals and relaunches post nothing, so one lease makes one pair: [#182](https://github.com/yahyabedirhan/shipyard/issues/182) "Notifications when a lease starts and ends".

## 0.1.0 (2026-10-03)

Agents steer and capture the app, each build carries only the modules it uses, the rough edges pings left are fixed, and releasing is written down for agents. It finishes every issue open on 2026-10-03, as [#160](https://github.com/yahyabedirhan/shipyard/issues/160) "Spec: clean-slate, every open issue finished, app control, modules by concern and the 0.1.0 release" planned, in the clean-slate pull request. [Release](https://github.com/yahyabedirhan/shipyard/releases/tag/v0.1.0).

- **App control.** On the Mac, `shipyard app open`, `quit` and `status` open, quit and ask the app; `shipyard panel open`, `close`, `fold`, `unfold`, `show-more` and `tab` steer its panel; `shipyard screenshot <file.png> [--appearance light|dark]` saves the open panel, and falls back to the app's own rendering, saying so, when the screen can't be captured; and `shipyard app open --demo <folder>` runs the app on that folder's configuration and state without touching yours. The requests go over a socket only your user can reach, and the shipyard skill and `AGENTS.md` teach agents the commands: [#166](https://github.com/yahyabedirhan/shipyard/issues/166) "Open, quit and ask the app from the shipyard command", [#167](https://github.com/yahyabedirhan/shipyard/issues/167) "Steer the panel from the shipyard command", [#168](https://github.com/yahyabedirhan/shipyard/issues/168) "Launch shipyard on demo data", [#169](https://github.com/yahyabedirhan/shipyard/issues/169) "Capture the panel from the shipyard command" and [#170](https://github.com/yahyabedirhan/shipyard/issues/170) "Teach agents app control, in the skill and AGENTS.md".
- **Modules by concern.** The Linux `shipyard` is built from the command and pings modules only, and the Mac's `shipyard` links reading `config.toml` and the control client but never the app's rules. Where a ping is filed is one interface with a Linux and a Mac implementation, not a platform check. ADR 0006 and the low-level design record the split. 0.1.0 is the first release with the Linux `shipyard` files and their `.sha256` files attached: [#164](https://github.com/yahyabedirhan/shipyard/issues/164) "Ship a Linux shipyard built from pings code only", [#165](https://github.com/yahyabedirhan/shipyard/issues/165) "The Mac shipyard links Config, never the app's rules" and [#161](https://github.com/yahyabedirhan/shipyard/issues/161) "Write the module design and ADR 0006 into the docs".
- **Ping fixes.** `shipyard ping` files against the `config.toml` the app reads, and is refused when every project it goes under hides pings. The app re-reads pings only when a ping changes, a `--herdr` ping focuses its pane in the named Herdr session it came from, a remote ping filed only after its selectors resolve notifies once, and a replaced ping's age starts again: [#126](https://github.com/yahyabedirhan/shipyard/issues/126) "The shipyard command reads the same config.toml as the app", [#127](https://github.com/yahyabedirhan/shipyard/issues/127) "Tell the agent when its ping shows nowhere", [#128](https://github.com/yahyabedirhan/shipyard/issues/128) "Re-read pings only when a ping changes", [#129](https://github.com/yahyabedirhan/shipyard/issues/129) "Focus --herdr pings from a named Herdr session", [#146](https://github.com/yahyabedirhan/shipyard/issues/146) "A remote ping filed under a project only after its selectors resolve still notifies" and [#150](https://github.com/yahyabedirhan/shipyard/issues/150) "Decide whether a replaced ping's age starts again".
- **Releases.** `AGENTS.md` gains a Releases section: an agent cuts a release end to end, then carries it, and any skill change, to the Mac and the remote machines. This changelog records 0.0.5 to 0.0.7, each tagged at the commit it ended on: [#162](https://github.com/yahyabedirhan/shipyard/issues/162) "Write how agents release and carry changes to the machines" and [#163](https://github.com/yahyabedirhan/shipyard/issues/163) "Record 0.0.5 to 0.0.7 in a changelog, with tags".
- **Docs and screenshots.** The README's three example screenshots are retaken with the current build, and the skill and the README name the limit that a remote ping's click can't switch the Mac's Herdr window to its machine: [#83](https://github.com/yahyabedirhan/shipyard/issues/83) "Retake the README's three example screenshots with the current build" and [#152](https://github.com/yahyabedirhan/shipyard/issues/152) "A remote ping's click can't switch the Mac's Herdr window to its machine".
- **A test audit** left one owner test per contract across the ping, CLI and Herdr tests: [#130](https://github.com/yahyabedirhan/shipyard/issues/130) "Audit the ping, cli and herdr tests after 0.0.6".
- Small leftovers from 0.0.2's final review are tidied: [#84](https://github.com/yahyabedirhan/shipyard/issues/84) "Tidy up small leftovers from 0.0.2's final review".
- **Faster CI.** CI runs once per pull request push and shares the SDK module cache: [#157](https://github.com/yahyabedirhan/shipyard/pull/157) "build: run ci once per pull request push and share the sdk module cache".
- The shipyard skill compares pinging from the Mac with pinging from another machine: [#158](https://github.com/yahyabedirhan/shipyard/pull/158) "docs(skill): compare pinging from the mac and from another machine, and start --from with the agent's name".
- Shipyard is licensed under MIT, and the bundled agent logos' notices are in `THIRD-PARTY-NOTICES.md`: [#159](https://github.com/yahyabedirhan/shipyard/pull/159) "docs: license shipyard under mit and give the bundled logos' notices a home".
- The version bump, in the clean-slate pull request.

## 0.0.7 (2026-10-03, tag only)

The fixes from the first QA round of pings, and one ping number per project.

- **Pings read like the rows beside them.** Gray ping icons, the ping's number on its line, the sending agent's real logo and kebab-case name, and failures as a few words on the row ("Pane gone", "No app", and "Offline" or "No machine" for a remote machine) with the whole reason in the hover card. A Herdr ping's click brings forward the `[herdr] terminal`, or else the terminal the ping was sent from. The menu orders its kinds as pull requests, pings, issues, runs: [#148](https://github.com/yahyabedirhan/shipyard/pull/148) "fix: the rough edges pings qa round 1 found (0.0.7)".
- **The Mac numbers pings per project, in the order they arrive.** Every ping in a project, local or remote, gets the next number, like issue numbers, so a smaller number always means earlier; the numbers live in the app's state. `shipyard ping` prints only the id again: [#155](https://github.com/yahyabedirhan/shipyard/pull/155) "feat(menu): the mac numbers pings per project, in the order they arrive (0.0.7)".
- A handoff for the remote pings follow-ups: [#149](https://github.com/yahyabedirhan/shipyard/pull/149) "docs(handoff): remote pings follow-ups from the mac".

## 0.0.6 (2026-10-02, tag only)

Pings from agents on your other machines, through Herdr, and faster builds.

- **Remote pings.** Agents on other machines send `shipyard ping` as on the Mac, and a blocked agent pings by itself through the herdr-shipyard plugin. The Mac reads each machine listed under `[remote] machines` through Herdr's own connection (never SSH), files, notifies and lists its pings, shows a quiet line for a machine it can't reach, and focuses the agent's pane on that machine when you click. The `linux cli` workflow builds static Linux `shipyard` files for each release: [#143](https://github.com/yahyabedirhan/shipyard/pull/143) "feat: remote pings, from agents on my other machines through herdr (0.0.6)".
- **Faster builds.** CI builds once, caches `.build` between runs, and bundles the app only on `main` and tags: [#142](https://github.com/yahyabedirhan/shipyard/pull/142) "ci: build once, cache .build and bundle only on main and tags".

## 0.0.5 (2026-10-02, tag only)

Pings from agents through the `shipyard` command, plus what 0.0.4 planned: the project setup and the menu freeze fix.

- **Pings.** The app bundles a `shipyard` command. `shipyard ping "…"` files a short message under the projects watching the repository it runs in, notifies under the new `ping.sent` event, and on a click opens a link, an app or a Herdr tab. `shipyard ping withdraw` takes one back, and its banner with it. New settings: `[defaults.pings]` `show` and `seen-window`, and `[herdr] terminal`: [#106](https://github.com/yahyabedirhan/shipyard/pull/106) "feat: pings, sent by agents through the shipyard cli (0.0.5)".
- **The menu no longer freezes.** Its measured scroll view stopped looping its layout: [#95](https://github.com/yahyabedirhan/shipyard/pull/95) "fix(panel): stop the menu's measured scroll view looping its layout".
- **The project setup for agents**: [#90](https://github.com/yahyabedirhan/shipyard/pull/90) "chore: audit the repo with set-up-project and keep two memory notes", [#91](https://github.com/yahyabedirhan/shipyard/pull/91) "chore: adopt the skills repo's folder standard for agent records", [#92](https://github.com/yahyabedirhan/shipyard/pull/92) "refactor: rename context.md to glossary.md and update issue-tracker.md" and [#93](https://github.com/yahyabedirhan/shipyard/pull/93) "docs(agents): create an effort label only when it's missing".
- A test audit pruned the tests that didn't earn their keep: [#123](https://github.com/yahyabedirhan/shipyard/pull/123) "test: prune tests that don't earn their keep, with a test audit".

## 0.0.2 (2026-09-26)

Each project chooses whose items it shows and how it arranges them, watches whole groups of repositories, starts from a preset, and signs in to GitHub without the GitHub CLI. Every 0.0.1 configuration file still works. [Release](https://github.com/yahyabedirhan/shipyard/releases/tag/v0.0.2).

- **Filters** by author, state and review request, for every project or one; **closed items for as long as you like** with `closed-window` and `finished-window`, which replace `closed-window-days` and `finished-window-hours`; **repository groups** (`my-org/*`, `owned`, `organizations`, `collaborator`, `anywhere`); **arranging** with `group-by`, `sort-by`, `subsections` and `show-first`; **presets and onboarding**; **Sign in with GitHub** on a redesigned connect screen; the olive khaki logo; and the agent skill installs again with `npx skills add`: [#71](https://github.com/yahyabedirhan/shipyard/pull/71) "feat: build shipyard 0.0.2, filters, repository groups, arrangement, presets and sign-in".
- **A hover card** replaces macOS's native tooltips: [#75](https://github.com/yahyabedirhan/shipyard/pull/75) "feat(panel): replace native tooltips with a hover help card".
