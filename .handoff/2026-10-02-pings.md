## Decisions settled in the grilling (beyond the spec)

The spec (#96) holds the full result. A few things the spec only implies:

- **Simplicity over special cases.** `ping.sent` is an ordinary event; there's no "on unless turned off" exception. The maintainer's own `config.toml` lists its own rules, so after the release `ping.sent` needs adding there; say so in the pull request as a post-merge follow-up (done through the shipyard skill, not by you).
- **Ids are global**, the simplest option.
- **`--from` is only what the agent passes**; nothing is inferred from Herdr.
- **The CLI is a new Swift target** (the `shipyard` executable) bundled in `Shipyard.app`, sharing `ShipyardCore`. ADR 0004 explains why a CLI despite ADR 0001.
- **Test seams** (agreed with the maintainer): the `Shipyard` orchestrator through the existing `Harness`, and the ping command as a core function; most stories are tested end to end across both through the shared ping store.
