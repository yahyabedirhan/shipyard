1. **Bug: a herdr ping's click doesn't move the view.**
   - "Back here" was sent from pane `w1G:p3` (tab `w1G:t3`) and clicked from a *local* herdr tab, not another machine. The app marked it seen, so `HerdrFocus` reported success, but the maintainer's herdr view stayed where it was.
   - Diagnose it: run the same `herdr` commands the app runs (`pane get`, then `tab focus`) and compare. Check which `herdr` binary and socket the app reaches from its Finder-launched environment, against the maintainer's server (`~/.config/herdr/herdr.sock`, Herdr 0.9.3). Find out whether `tab focus` moves an attached client's view across workspaces.
   - Herdr facts verified 2026-10-02: a focus through `--machine` moves the client's view only when it's showing that machine. Herdr's docs: https://herdr.dev/llms.txt.
   - File it as a bug in 0.0.7 and fix it. Re-test with Ghostty now configured.
2. **The empty number column.**
   - Ping rows leave the issue/PR number column empty, so there's a gap between the icon and the title. The maintainer's idea: give each ping a unique number, as issues and PRs have.
   - Settle with the maintainer what the number is before building: for example a per-machine counter shown as `#n`, how it relates to the ping's id, and whether it survives replace and withdraw. Put the decision in the ticket.
   - 0.0.6 adds remote pings (`shipyard://ping/<machine>/<id>`), so the numbering must stay unique across machines, or be per machine with the machine shown.
3. **Sender icons.**
   - A ping from a known agent (claude, codex, opencode, cursor, pi, and others) shows that agent's icon in place of the action icon, or beside it. Settle which with the maintainer.
   - Research where each agent's icon is published in its open-source project or brand kit, and its licence. Use the **research** skill, and Exa's search and fetch first. Clone repositories into `~/Developer/open-source/`, and cite repository and commit in any committed file.
   - Bundle only icons whose licence allows it. Fall back to the action icon for unknown senders.
4. **"Waiting" did nothing on click.** A ping without an action only turns seen when clicked, as designed, and the maintainer expected something. Ask whether a no-action ping should look different (no pointer affordance, or a hint in its hover card) before changing anything.
5. **"Broken"** recorded its failure (`No app named No Such App`). Confirm with the maintainer that the red reason showed on the row.
