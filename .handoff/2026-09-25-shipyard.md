## What the builder should know

- **Toolchain:** Swift 6.3 with Command Line Tools only, no Xcode. Build with SwiftPM and a Makefile that bundles the `.app` (ghbar's Makefile and `Package.swift` show how). No Developer ID: ad-hoc signing only.
- **ghbar** (`~/Developer/open-source/ghbar`) is a reference to learn from, not to copy. Worth reading: `TokenProvider.swift` (finding `gh` from an `.app`), `DeviceFlowAuth.swift`, `RefreshGate.swift`, `SeenStore.swift` (keep seen and notified separate), its tests and fixtures. Its comments are in Turkish.
- **Needs the user (#3):** the device flow needs an OAuth App registered under the user's GitHub account, with device flow enabled, and its client ID. Ask for it. The `gh` token path works without it, so the rest of #3 needn't wait.
- **Main test seam (#5 onwards):** drive the orchestrator end to end, with the network stubbed at the URL-loading layer from recorded fixtures, temporary configuration and app-state directories, a recording notifier and an injectable clock. Assert on the menu model and the notifications posted.
- **Versioning:** start at 0.0.1, stay below 0.1.0 until the user calls the public launch.
- **Not in scope:** anything in the spec's Out of Scope. Don't add a CLI or a settings window (ADR 0001).
