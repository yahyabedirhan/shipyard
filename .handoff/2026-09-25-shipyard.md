## What the builder should know

- **ghbar** is a reference to learn from, not to copy. Worth reading: `TokenProvider.swift` (finding `gh` from an `.app`), `DeviceFlowAuth.swift`, `RefreshGate.swift`, `SeenStore.swift` (keep seen and notified separate), its tests and fixtures. Its comments are in Turkish.
- **The core/app boundary:**
  - `ShipyardCore` imports only Foundation (FoundationNetworking on Linux) and TOMLDecoder.
  - Apple-only services come through the core's ports (token store, notifier, clock, URL opener); the core has in-memory doubles for tests, and phase 2 supplies the real ones.
  - Watch for Darwin-only Foundation APIs: `DispatchSource` file-system sources, `NSWorkspace`, `Security`. They belong in the app.
- **Main test seam (#5 onwards):** drive the core's `Shipyard` orchestrator end to end:
  - the network stubbed at the URL-loading layer from recorded GitHub fixtures;
  - temporary configuration and app-state directories;
  - a recording notifier and an injectable clock.

  Assert on the menu model and the notifications posted.
- **Needs the user (#4, #14):** the device flow needs an OAuth App registered under the user's GitHub account, with device flow enabled, and its client ID. Ask for it. The `gh` token path and tests with a placeholder ID don't need to wait.
- **Versioning:** start at 0.0.1, stay below 0.1.0 until the user calls the public launch.
- **Commits:** follow `AGENTS.md` (lowercase Conventional Commits, `Co-Authored-By` as the only trailer).
- **Not in scope:** anything in the spec's Out of Scope. Don't add a CLI or a settings window (ADR 0001).
