## What the builder should know that isn't in the tickets

- **Start with #55, #56 and #57.** Nothing blocks them. #56 builds `Listing`, the seam every later filter uses. #23 is the maintainer's: registering the OAuth App and posting its client ID. #14 waits on it.
- **Keep these in sequence, not parallel:** #14 and #66 both change onboarding's screens. #63 and #64 both touch the list layout and `RowHighlight`.
- **#14's body is out of date on verification.** It says to verify by running the app on a Mac. Agents never drive the Mac: no clicking, scripting, screenshots, key events or self-built GUI harnesses (AGENTS.md, Testing). Verify only with `make test` and `swift build`.
- **QA:** every visual, interactive ticket (#62, #63, #64, #66, #14, and anything else the maintainer sees) gets **blocking** QA once built and installed. That means a `ready-for-qa` label, assigned to the maintainer, with how to use and try it. The maintainer closes it; agents never close a ticket in QA. The pull request doesn't merge until every QA ticket is closed. Configuration, skill and agent-only changes get no QA ticket. See `docs/agents/triage-labels.md`.
- **Installing for QA:** `make install` replaces `/Applications/Shipyard.app`. Run it one at a time, and only from the orchestrator. Tickets can build in parallel sub-agent worktrees, but installs are serialized.
- **Bugs** found while building or in QA become tickets, or update the ticket that owns the behaviour, with the maintainer's screenshots when there are any (`docs/agents/issue-tracker.md`).
- **Drafts and scratch files** go in the worktree's `.scratch/` (gitignored), never in a temp folder outside the repo.
- **Code, comments and test names carry no issue numbers.** Commit messages, pull requests and docs do. Commits are lowercase Conventional Commits with the `Co-Authored-By` trailer only, no `Claude-Session` trailer (CLAUDE.md).
- **Native over custom** in the UI: the maintainer rejected hand-rolled animation before (#53's fix removed the fold animation's sweep with native SwiftUI).
- **The pull request** goes through the **to-pr** skill.
